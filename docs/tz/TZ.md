## 1. Наименование и цель

**Продукт (рабочее имя):** компилятор диалекта классического PL/I с траекторией к Subset G  
**Код имени (TBD):** см. [`../decisions/OPEN.md`](../decisions/OPEN.md) — CLI / runtime  

**Цель:** получить **исполняемые** программы на выбранном подмножестве PL/I через транспиляцию в C, с парсером классической поверхности (включая keywords-as-names) с первого исполняемого уровня.

**Не цель:** GCC language frontend; порт `pl1gcc`; IBM Enterprise PL/I; полный ANSI full как KPI.

## 3. Объект разработки

| Компонент | Описание |
|-----------|----------|
| Компилятор (frontend) | Lex → parse → AST → sema → HIR → эмит C |
| Runtime | Библиотека на C (I/O минимум, типы, позже builtins) |
| Driver / CLI | Оркестрация: `.pli` → `.c` → системный `cc` → бинарник |
| Тесты | `must-run` / `must-parse` / `out-of-scope` + golden |
| Документация | Манифест, ТЗ, SPEC, ADR, user notes (позже) |

**Вне объекта:** нативный x64 backend; LLVM backend на этапе L0 (допустим каркас позже); вхождение в дерево GCC.

## 4. Уровни поставки (acceptancе)

### L0 — «существует» (первый вертикальный срез)

**Парсер (уже амбициозный):** keywords-as-names; PROC/BEGIN/DO/END/IF; DECLARE с основными атрибутами (часть parse-only); выражения; scopes.

**Исполнение:**
- `PROC OPTIONS(MAIN)`, присваивание, арифметика
- `FIXED BIN`, `FLOAT`, `CHAR(n)` (BIT — по готовности)
- `AUTOMATIC` / `STATIC` / `PARAMETER` (модель — ADR)
- `IF` / простые `DO`
- `PUT LIST` / `PUT SKIP LIST` → runtime
- Неподдерживаемое после parse → **диагностика not-implemented**, не молчаливый wrong code

**Критерий приёмки L0:** набор `must-run` из SPEC собирается в бинарник и даёт ожидаемый stdout; набор `must-parse` (вкл. keywords-as-names) парсится; CI зелёный.

### L1 — «утилиты»

DO/SELECT шире; массивы; простые структуры; больше builtins; `%INCLUDE` / `%REPLACE` по мере ADR.

### L2 — «наследие к G»

Расширение пересечения с Subset G по приоритету эталонных программ; DECIMAL/I/O/preprocessor — по SPEC.

### Horizon G

Документированная совместимость с Subset G на заявленном пересечении + список отличий.

## 7. Ограничения и допущения

- Целевая ОС разработки/прогона L0: Windows и/или Linux (уточнить в ADR host platforms).  
- Кодовая страница исходников L0: ASCII / разумный UTF-8 subset (ADR).  
- Не требуется совместимость с object-кодом IBM / LE.  
- ULM Modula-2 — параллельный проект; ресурсы не смешивать в один backend.
